
----------------------------------------------------------------
ЗАДАЧА 1. Полное бинарное дерево
----------------------------------------------------------------

Условие заполненности уровней.
Дерево называется полным (complete), если все его уровни, кроме,
возможно, последнего, заполнены полностью, а узлы последнего уровня
стоят слева направо, без "дыр" между ними.

Способ обхода и почему BFS.
Полнота определяется именно ПО УРОВНЯМ, поэтому естественный
инструмент — обход в ширину (BFS). BFS обходит узлы уровень за
уровнем, и внутри каждого уровня — слева направо, что совпадает
с определением полного дерева. DFS (pre/in/post-order) не даёт
такого порядка и потребовал бы дополнительно отслеживать индексы
узлов, что сложнее и не нужно.

Алгоритм.
Кладём корень в очередь. В BFS кладём в очередь и nullptr-детей.
Как только впервые встретили nullptr, ставим флаг seenNull = true.
С этого момента любой реальный узел, встреченный в очереди,
означает, что слева от него осталась "дыра", — значит, дерево
не полное. Если обход завершился без нарушений — дерево полное.

Корректность.
Первый nullptr — это граница заполненной части последнего уровня.
Всё, что идёт дальше, должно быть nullptr-ами; иначе между
заполненными узлами есть разрыв, что противоречит определению
полноты. Условие "if (seenNull && cur != nullptr) return false"
проверяет ровно это.

Сложность.
  Время:  O(n) — каждый узел (включая nullptr-детей листьев)
          посещается один раз.
  Память: O(n) в худшем случае (ширина последнего уровня).


----------------------------------------------------------------
ЗАДАЧА 2. Объединение K отсортированных массивов
----------------------------------------------------------------

Идея.
Храним в МИН-КУЧЕ по одному "текущему" элементу от каждого массива —
самый маленький ещё не взятый элемент этого массива. На каждом шаге
достаём из кучи глобальный минимум, записываем его в результат
и вместо него кладём следующий элемент из того же массива.

Почему мин-куча эффективна.
Наивный вариант "сливать по одному массиву" в худшем случае даёт
O(N*K): каждый элемент приходится сравнивать с головой каждого из K
массивов. Мин-куча размера K всегда содержит "головы" всех массивов,
и глобальный минимум находится за O(log K), а не за O(K). Для K = 2
разница огромна: log 2 = 1 против K = 2.

Алгоритм.
1. Для каждого непустого массива i кладём в кучу (arrays[i][0], i, 0).
2. Пока куча не пуста: достаём минимум, пишем в результат, и если
   в его массиве есть следующий элемент — кладём его в кучу.

Корректность.
Индукция по числу извлечённых элементов: в любой момент куча
содержит самый маленький ещё не извлечённый элемент каждого массива
(голова соответствующего массива). Минимум кучи — это глобально
наименьший из всех оставшихся, поэтому извлекается в правильном
порядке. Следовательно, результирующий массив отсортирован
по возрастанию.

Сложность.
  Время:  O(N log K), где N — суммарное число элементов,
          K — число массивов (N извлечений и до N вставок,
          каждая — O(log K)).
  Память: O(K) под кучу + O(N) под результат.

Сравнение: "собрать всё и отсортировать" — O(N log N),
что хуже при K << N.


----------------------------------------------------------------
ЗАДАЧА 3. K-й наименьший / наибольший элемент массива
----------------------------------------------------------------

Идея.
  Для K-ГО НАИМЕНЬШЕГО достаточно помнить K самых маленьких
  элементов. Это делает max-куча размера K: если после вставки
  куча превышает K элементов, удаляем её максимум — он заведомо
  не входит в топ-K наименьших. По окончании в корне max-кучи —
  k-й наименьший.

  Для K-ГО НАИБОЛЬШЕГО — симметрично: min-куча размера K,
  удаляем минимум.

Почему куча, а не сортировка.
Сортировка даёт O(n log n) и O(n) памяти. Полная куча тоже
O(n log n). А КУЧА РАЗМЕРА K даёт O(n log K) времени и O(K) памяти —
это выигрыш, если K мало по сравнению с n. Кроме того, такой подход
работает ПОТОКОВО: массив не нужно хранить целиком, достаточно
подавать элементы по одному.

Альтернативы.
  - Quickselect: O(n) в среднем, но O(n^2) в худшем и модифицирует
    массив.
  - Полная сортировка: O(n log n) всегда, но хуже по времени при
    малом K и требует O(n) памяти.

Подход с кучей даёт СТАБИЛЬНУЮ ГАРАНТИЮ O(n log K) без худших
случаев и минимум памяти.

Корректность.
Инвариант: после обработки i элементов в max-куче лежат K наименьших
из первых i элементов. База: i = 0 — тривиально. Шаг: добавляем x;
если куча > K, удаляем её максимум — это наибольший из K+1 элементов,
значит, он не может быть среди K наименьших; остальные K — это
K наименьших из i элементов. По индукции в конце в max-куче —
K наименьших всего массива, в корне — k-й наименьший.

Сложность.
  Время:  O(n log K) (n вставок и не более n извлечений,
          каждое O(log K)).
  Память: O(K).


----------------------------------------------------------------
ЗАДАЧА 4. K-й наименьший / наибольший элемент в BST
----------------------------------------------------------------

Идея и свойства BST.
В бинарном дереве поиска IN-ORDER обход (левый -> корень -> правый)
выдаёт элементы строго в ВОЗРАСТАЮЩЕМ порядке — это фундаментальное
свойство BST: все ключи в левом поддереве меньше узла, все в правом —
больше. Значит, k-й элемент этой последовательности — ровно
K-Й НАИМЕНЬШИЙ в дереве. Соответственно, ОБРАТНЫЙ IN-ORDER
(правый -> корень -> левый) даёт убывающий порядок, и его k-й
элемент — K-Й НАИБОЛЬШИЙ.

Почему итеративно, а не рекурсивно.
При рекурсивном обходе пришлось бы либо использовать глобальный
счётчик, либо передавать его по ссылке и явно прерывать рекурсию —
что неудобно. Итеративная версия с явным стеком:
  - не требует изменять дерево и не хранит ничего лишнего;
  - ОСТАНАВЛИВАЕТСЯ СРАЗУ после k-го элемента, не обходя оставшиеся
    n - k узлов;
  - использует стек размера O(h), а не O(n) рекурсивных вызовов.

Корректность.
In-order обход посещает узлы в порядке возрастания ключей. Счётчик
уменьшается при каждом посещении; когда он дошёл до нуля — текущий
узел и есть k-й наименьший. Для k-го наибольшего — симметрично
в обратном порядке.

Сложность.
  Время:  O(h + k), где h — высота дерева: сначала спускаемся
          по левой ветке (<= h), затем делаем k шагов. Для
          сбалансированного BST h = O(log n), итого O(log n + k).
  Память: O(h) под стек.


----------------------------------------------------------------
ЗАДАЧА 5. Balance factor
----------------------------------------------------------------

Определение.
  balance_factor(v) = height(left(v)) - height(right(v)).

Как вычисляется высота.
Используем стандартное определение:
  - height(nullptr) = 0 (пустое поддерево),
  - height(лист)    = 1,
  - height(v)       = 1 + max(height(left(v)), height(right(v))).

То есть высота — число узлов на самом длинном пути от v вниз
(можно и через число рёбер — тогда лист имел бы высоту 0; значение
balance_factor при этом не изменится, поскольку константа
сокращается в разности).

Почему обход пост-порядковый.
Чтобы вычислить balance_factor(v), нужны высоты ОБОИХ его детей.
Значит, дети должны быть обработаны РАНЬШЕ узла. Пост-order
(левый -> правый -> корень) это обеспечивает: к моменту вычисления
balance_factor(v) оба поддерева уже полностью обработаны и известны
их высоты. Функция возвращает высоту текущего поддерева, и это
значение "поднимается" к родителю.

Корректность.
Индукция по структуре дерева: для nullptr высота = 0 по определению.
Для узла v по индукционному предположению высоты leftH и rightH уже
вычислены корректно; тогда balance_factor(v) = leftH - rightH
по определению, а возвращаемая высота 1 + max(leftH, rightH) — тоже
по определению. Значит, все узлы получают правильные значения.

Сложность.
  Время:  O(n) — каждый узел обрабатывается ровно один раз
          (никакого повторного пересчёта высот, в отличие от
          "наивного" подхода с отдельной функцией height() для
          каждого узла, который дал бы O(n^2)).
  Память: O(h) под рекурсивный стек (O(n) в вырожденном случае,
          O(log n) для сбалансированного дерева).


----------------------------------------------------------------
ЗАДАЧА 6. Зеркальное дерево
----------------------------------------------------------------

Определение зеркального дерева.
  mirror(T) — дерево с тем же корнем, у которого:
    - левое поддерево  = mirror(правое поддерево T),
    - правое поддерево = mirror(левое поддерево T).

Алгоритм.
1. Если корень nullptr — ничего не делать.
2. Поменять местами left и right текущего узла.
3. Рекурсивно отразить левое и правое поддеревья.

Почему алгоритм корректен (доказательство по индукции).
  - База. Пустое дерево (nullptr) зеркально самому себе —
    рекурсия сразу выходит, ничего не меняя.
  - Индукционный переход. Пусть для всех деревьев размера < n
    алгоритм корректен. Рассмотрим дерево T размера n с корнем r
    и поддеревьями L и R. После swap(r->left, r->right) у r слева
    стоит R, справа — L. Рекурсивные вызовы mirrorTree(R)
    и mirrorTree(L) по индукционному предположению превращают R
    в mirror(R), а L — в mirror(L) (их размеры меньше n). Итог:
    у r слева mirror(R), справа mirror(L) — ровно то, что требует
    определение зеркального дерева.
  - По принципу математической индукции алгоритм корректен для
    любого бинарного дерева.

Важно: обход может быть ЛЮБЫМ (pre-, in-, post-order) — важен лишь
факт, что каждый узел обрабатывается ровно один раз. В реализации
используется pre-order (swap -> левое -> правое), что удобно:
swap сразу на текущем узле, а затем — рекурсия в оба поддерева.

Сложность.
  Время:  O(n) — каждый узел посещается ровно один раз,
          swap — O(1).
  Память: O(h) под рекурсивный стек; O(n) в худшем случае
          вырожденного дерева (цепочки), O(log n) для
          сбалансированного.
